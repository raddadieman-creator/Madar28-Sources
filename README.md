# مدار 28

المنصة الرقمية للمتوسطة الثامنة والعشرين بالمدينة المنورة — لأولياء الأمور والطالبات ومنسوبات المدرسة.

**المرحلة الأولى (هذه النسخة):** واجهة كاملة متجاوبة، تنقّل بين الأقسام، بحث موحّد، تقويم هجري/ميلادي تفاعلي، والمساعد «رُشد» يعمل محليًا. لا توجد لوحة تحكم ولا تسجيل دخول ولا قاعدة بيانات بعد؛ هذه للمرحلة الثانية.

---

## التشغيل على جهازك

المتطلبات: [Node.js](https://nodejs.org) الإصدار 18 أو أحدث.

```bash
npm install        # مرة واحدة لتنزيل المكتبات
npm run dev        # تشغيل نسخة التطوير على http://localhost:5173
npm run build      # بناء نسخة النشر في مجلد dist
npm run preview    # معاينة نسخة النشر محليًا
```

## النشر على GitHub Pages

1. أنشئي مستودعًا جديدًا على GitHub (مثلًا `madar-28`) وارفعي ملفات المشروع إلى الفرع `main`.
2. من المستودع: **Settings ← Pages ← Build and deployment ← Source** واختاري **GitHub Actions**.
3. أي رفع جديد إلى `main` يبني الموقع وينشره تلقائيًا عبر الملف `.github/workflows/deploy.yml`.
4. الرابط سيكون: `https://اسم-الحساب.github.io/madar-28/`

**المسار الأساسي (base path):** يُضبط تلقائيًا أثناء النشر على اسم المستودع، فلا تحتاجين تعديله إن غيّرتِ اسم المستودع.
وعند البناء اليدوي يُستخدم المسار النسبي `./` الذي يعمل في أي مجلد.

**تحديث الصفحة مباشرة:** المنصة تستخدم روابط بالشكل `/#/services`، فيعمل فتح أي رابط أو تحديث الصفحة على GitHub Pages دون أخطاء 404.

## تعديل المحتوى (دون لمس الواجهات)

كل المحتوى في مجلد `src/data/`. عدّلي النص واحفظي وارفعي التعديل، فيُحدَّث الموقع.

| الملف | المحتوى |
|---|---|
| `school.ts` | اسم المدرسة، الترحيب، الرؤية والرسالة والأهداف، كلمة المديرة، الهيكل الإداري، العنوان، رسالة الأسبوع لأولياء الأمور |
| `services.ts` | الخدمات والروابط الرسمية، ودليل «ماذا أفعل إذا؟» |
| `guidance.ts` | موضوعات التوجيه الطلابي وروابط أدلة PDF |
| `mawhiba.ts` | برامج موهبة والفرص |
| `volunteer.ts` | المبادرات وشروط المشاركة والفرص والإنجازات |
| `events.ts` | الفعاليات والمناسبات (التاريخ بالميلادي، والهجري يُحسب تلقائيًا) |
| `announcements.ts` | الإعلانات (تثبيت، تاريخ انتهاء) |
| `contacts.ts` | دليل التواصل: الأسماء والمسميات والاختصاصات والقنوات الرسمية (الأرقام في ملف خاص، انظري أدناه) |
| `values.ts` | القيم المدرسية وقيمة الأسبوع |
| `faq.ts` | قاعدة معرفة «رُشد» والأسئلة المقترحة |
| `navigation.ts` | عناصر القوائم |

### قواعد مهمة

- **المحتوى التجريبي:** أي عنصر فيه `status: 'draft'` يظهر عليه وسم «تجريبي». بعد اعتماده من المدرسة غيّريه إلى `'approved'`.
- **أدلة PDF:** ضعي الملف في `public/guides/` ثم اكتبي في `guidance.ts`: `pdf: { label: 'اسم الدليل', url: 'guides/اسم-الملف.pdf' }`.
- **الإعلانات:** `pinned: true` يثبّت الإعلان أعلى القائمة، و`expires: 'YYYY-MM-DD'` يخفيه تلقائيًا بعد ذلك التاريخ.
- **الفعاليات:** تنتقل تلقائيًا إلى الأرشيف بعد انتهائها، وتظهر «جارية الآن» خلال مدتها.
- **قيمة الأسبوع:** تتغير أسبوعيًا بالترتيب. لتثبيت قيمة ضعي معرّفها في `valuesConfig.featuredValueId`.
- **مواعيد الاختبارات والإجازات** الحالية أمثلة تجريبية؛ استبدليها بمواعيد التقويم الدراسي المعتمد.

### إضافة سؤال إلى «رُشد»

أضيفي عنصرًا في `src/data/faq.ts`:

```ts
{
  id: 'uniform',
  question: 'ما الزي المدرسي المعتمد؟',
  answer: 'الإجابة المعتمدة من المدرسة…',
  keywords: ['زي', 'مريول', 'لبس المدرسة'],   // الكلمات التي يكتبها الناس فعلًا
  to: { label: 'عن المدرسة', path: '/about' },  // اختياري
  contactId: 'vice',                         // اختياري: معرّف المسؤولة في contacts.ts
  category: 'عام',
}
```

## الهوية

- **اسم المنصة:** مدار 28 — **الوصف الرسمي:** المنصة الرقمية للمتوسطة الثامنة والعشرين.
- **أيقونة المنصة:** نواة في حلقة داخلية يحيط بهما مدار مفتوح، ونقطة عند طرف المدار ترمز إلى الحركة والترابط.
  ملفاتها: `public/madar-icon.svg` و`madar-icon-192.png` و`madar-icon-512.png` و`favicon.png`، والمكوّن `src/components/brand/Madar.tsx`.
- **شعار المدرسة الرسمي** مستقل عن هوية المنصة: يظهر في الصفحة الرئيسية والتذييل فقط (`public/logo.webp`).
- لا يوجد ملف PWA أو Manifest في المشروع حاليًا.

## دليل التواصل وأرقام المسؤولات

الأسماء والمسميات والاختصاصات في `src/data/contacts.ts`، أما **الأرقام فمحفوظة في ملف خاص**:

```
private/contact-phones.json
```

> ✅ **الحالة الحالية:** اعتُمد نشر الأرقام بمراجعة مديرة المدرسة وموافقة جميع المسؤولات (أكتوبر 2026)، فأصبح الملف يُرفع مع المشروع وتظهر الأرقام في الموقع مع أزرار الاتصال وواتساب وحفظ جهات الاتصال.

قبل الاعتماد كان الملف مستبعدًا من GitHub عبر `.gitignore`، لأن مستودع GitHub Pages المجاني عام وأي رقم داخل ملفاته يصبح مكشوفًا. والآلية باقية لأي رقم جديد.

### متى يظهر الرقم في الموقع؟

لا يدخل الرقم ملفات الموقع المنشور إلا إذا تحقق **الشرطان معًا**:

| الحقل | المعنى |
|---|---|
| `"approved": true` | اعتمدت إدارة المدرسة نشر أرقام الدليل |
| `"consent": true` (لكل رقم) | تأكدت المدرسة من موافقة صاحبة الرقم |

ما لم يتحقق الشرطان، يُحذف الرقم أثناء البناء، فلا يظهر في الصفحة ولا في الكود. وتعرض البطاقة: «يُعرض الرقم بعد اعتماده من إدارة المدرسة».
أثناء التطوير على جهازك (`npm run dev`) تظهر كل الأرقام للمراجعة، مع تنبيه أنها غير منشورة.

### خطوات النشر بعد الاعتماد (لأي رقم جديد مستقبلًا)

1. في `private/contact-phones.json`: اجعلي `"approved": true`، و`"consent": true` لكل مسؤولة وافقت.
2. تأكدي أن السطر `private/contact-phones.json` في ملف `.gitignore` معطّل بعلامة `#` (وهو كذلك الآن).
3. ارفعي التعديل؛ يُنشر الموقع تلقائيًا بالأرقام المعتمدة فقط.

> ⚠️ عند رفع الملفات من موقع GitHub بالسحب والإفلات لا يُطبَّق `.gitignore`؛ فأي رقم في الملف يُرفع كما هو. لذلك لا تضيفي رقمًا جديدًا إلى الملف قبل اعتماده.

### إضافة مسؤولة نظام نور

1. في `contacts.ts`: أضيفي الاسم في الحقل `name` لبطاقة `noor`.
2. في `private/contact-phones.json`: أضيفي `"noor": { "phone": "05XXXXXXXX", "consent": false, "whatsapp": true }`.

### قواعد الدليل

- لا صور شخصية للمسؤولات؛ تظهر أيقونة الدور فقط.
- لا تُضاف أوقات تواصل (`hours`) إلا بعد اعتمادها من الإدارة.
- `active: false` يخفي البطاقة دون حذف بياناتها، و`order` يحدد ترتيبها.
- `"whatsapp": false` يخفي زر واتساب لمن لا تستخدمه على رقمها.
- الأسئلة الشائعة ودليل «ماذا أفعل إذا؟» ترتبط بالمسؤولة عبر معرّفها (`contactId`)، فتغيير الاسم أو المسمى لا يكسر الروابط.

### الجاهزية للوحة التحكم

حقول البطاقة مصممة لتطابق جدولًا في قاعدة البيانات يُدار من لوحة التحكم في المرحلة الثانية:

| الحقل | النوع |
|---|---|
| `id` | معرّف ثابت |
| `role`, `name`, `responsibility` | نص |
| `icon` | اسم الأيقونة |
| `topics` | قائمة كلمات للبحث |
| `phone`, `whatsapp` | الرقم، وتوفر واتساب |
| `consent`, `approved` | موافقة صاحبة الرقم، واعتماد الإدارة (يُسجَّل معهما من اعتمد ومتى) |
| `hours` | أوقات معتمدة فقط |
| `order`, `active` | الترتيب والإظهار |

وعند الربط يعيد الخادم الأرقام المعتمدة فقط، بالشكل نفسه، دون تعديل الواجهات.

## كيف يعمل «رُشد» الآن

- يجيب **فقط** من `faq.ts`، ويعرض مصدر الإجابة والروابط والمسؤولة المناسبة.
- إن لم يجد تطابقًا كافيًا يقترح صفحات ذات صلة، وإن لم يجد شيئًا يقول صراحة إنه لا يملك إجابة معتمدة.
- يرفض معالجة أي رسالة تتضمن رقم هوية أو جوال أو بريدًا، ويخفيها من المحادثة.
- كل شيء يجري داخل المتصفح؛ لا يُرسل أي نص إلى خادم، ولا يُحفظ شيء.
- القراءة الصوتية والإدخال الصوتي من خصائص المتصفح نفسه، وتظهر أزرارهما فقط حين يدعمها المتصفح (جودة الصوت العربي تختلف بين الأجهزة).

## بنية المشروع

```
src/
  data/          المحتوى القابل للتعديل
  types/         أنواع البيانات (العقد بين الواجهات ومصدر البيانات)
  services/      طبقة الوصول للبيانات + البحث + محرك رُشد + الاقتراحات
  lib/           أدوات: العربية، التواريخ الهجرية/الميلادية، الخصوصية، الصوت، ملفات التقويم
  components/    المكونات (layout, rushd, calendar, ui)
  pages/         صفحات المنصة
public/          الشعار والأيقونات وملفات PDF
```

## الجاهزية للمرحلة الثانية

- الصفحات لا تقرأ ملفات البيانات مباشرة؛ تمر كلها عبر `src/services/contentService.ts`.
  عند تعريف `VITE_API_URL` تتحول هذه الدوال إلى جلب البيانات من الخادم **دون تعديل أي صفحة**، بشرط أن يعيد الخادم البيانات بالأنواع نفسها في `src/types/content.ts`.
- نموذج «صوتك مسموع» يمر عبر `suggestionsService.ts`؛ الإرسال الفعلي يتفعّل تلقائيًا مع وجود الخادم، ويتوقع منه رقم متابعة.
- محرك «رُشد» في `rushdEngine.ts` منفصل عن واجهته، ويمكن استبداله باستدعاء خادم آمن مع الإبقاء على فحص البيانات الحساسة في المتصفح قبل الإرسال.

### ما يحتاج إعدادًا قبل المرحلة الثانية

| المتطلب | لماذا |
|---|---|
| استضافة للخادم وقاعدة بيانات (مثل Supabase أو Node.js + PostgreSQL) | GitHub Pages يستضيف ملفات ثابتة فقط، ولا يشغّل خادمًا ولا يحفظ بيانات |
| قرار الجهة المالكة للبيانات وسياسة الخصوصية المعتمدة | قبل جمع أي اقتراحات أو حسابات |
| حسابات المسؤولات وأدوارهن | لتسجيل الدخول ولوحة التحكم |
| نطاق (دومين) اختياري | إن أردتم رابطًا رسميًا بدل رابط GitHub |
